# Vitaly Video Suggestions

Telegram-бот **@vs_predlog_bot** и сайт для предложений зрителей. Заявки сначала попадают на модерацию и не появляются в публичной очереди без одобрения.

## Архитектура

- Папка docs: статический публичный сайт и админ-панель для Telegram Mini App.
- Файл src/index.js: Cloudflare Worker, Telegram webhook и API.
- Cloudflare D1: заявки, лимиты отправки и минимальный список банов.
- GitHub: исходный код. Секреты сюда не добавляются.

**Важно:** бот не скачивает и не открывает ссылки зрителей на сервере. Для YouTube-превью используется только стандартная картинка i.ytimg.com по проверенному ID ролика. Остальные поддерживаемые ссылки показываются без автоматически загружаемого превью. Это снижает риск SSRF и обработки вредоносных страниц.

## Защита

- Админ API проверяет подпись Telegram.WebApp.initData на сервере и сравнивает подтверждённый Telegram ID с ADMIN_TELEGRAM_ID. Проверка ID только в браузере не считается защитой.
- Telegram webhook проверяет секретный заголовок X-Telegram-Bot-Api-Secret-Token.
- Команды управления ботом разрешены только администратору. Бан и разбан выполняются по числовому Telegram ID, не по имени пользователя.
- При бане все заявки зрителя, его профиль и лимит отправки удаляются. В таблице банов остаётся Telegram ID и причина: эти минимальные данные нужны, чтобы отклонять новые заявки.
- На одного человека: 1 заявка в 60 секунд и максимум 5 за UTC-сутки. Повторная ссылка блокируется на 30 дней.
- Принимаются HTTPS-ссылки только с явно разрешённых видеосервисов либо обычный текст с названием фильма/видео. Список доменов находится в src/index.js.
- Пользовательский текст выводится на сайте как текст, а не HTML. Админ API не использует открытые CORS-запросы от неизвестных источников.
- Токен бота, webhook-секрет и другие приватные значения хранятся в Cloudflare Secrets, а не в файлах сайта.

Это защитные меры для MVP, а не гарантия абсолютной неуязвимости. После настройки следует включить уведомления Cloudflare и при публичном запуске добавить WAF rate-limit правило для API.

## Настройка с нуля

### 1. Подготовить Cloudflare Worker и базу D1

Установи Node.js LTS, скачай репозиторий и открой терминал в его папке:

~~~powershell
npm install
npx wrangler login
npx wrangler d1 create vitaly-video-suggestions
~~~

Команда D1 покажет database_id. Вставь его в wrangler.toml вместо REPLACE_WITH_D1_DATABASE_ID. Не вставляй Telegram ID, токен бота или webhook-секрет в файлы репозитория.

Создай таблицы и выполни первый деплой Worker:

~~~powershell
npx wrangler d1 execute vitaly-video-suggestions --remote --file=migrations/0001_init.sql
npx wrangler deploy
~~~

После первого деплоя скопируй адрес Worker вида https://vitaly-video-suggestions-api.ТВОЙ-АККАУНТ.workers.dev. До добавления секретов webhook ещё не будет готов к работе.

Теперь добавь секреты командами. Терминал попросит ввести каждое значение:

~~~powershell
npx wrangler secret put BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
~~~

- **BOT_TOKEN**: токен из BotFather. Не показывай его в чате, не добавляй в файлы и не публикуй скриншоты с ним.
- **TELEGRAM_WEBHOOK_SECRET**: случайная строка из латинских букв, цифр, дефиса и подчёркивания длиной 32-64 символа. Сохрани её локально, она понадобится для регистрации webhook.
- **ADMIN_TELEGRAM_ID** пока не задавай. Получим его через команду /id после запуска webhook. Иначе возникнет замкнутый круг: бот ещё не работает, а ID нужен для настройки бота.

### 2. Подключить Telegram к Worker и узнать свой ID

Запусти готовый PowerShell-скрипт из корня репозитория:

~~~powershell
powershell -ExecutionPolicy Bypass -File .\scripts\set-webhook.ps1
~~~

Он попросит Worker URL, а токен бота и webhook-секрет введёт через скрытый ввод. Скрипт не выводит их в консоль и при ошибке не печатает технический ответ Telegram, в котором может оказаться адрес API с токеном. Не запускай первоначальную настройку во время трансляции рабочего стола.

Если Telegram вернул `ok = True`, открой **@vs_predlog_bot** и отправь `/id`. Бот сообщит твой числовой Telegram ID. Сохрани его и введи в Cloudflare Secret:

~~~powershell
npx wrangler secret put ADMIN_TELEGRAM_ID
~~~

После этого при необходимости выполни `npx wrangler deploy`. Теперь сервер будет проверять именно этот ID. Ник и имя для администрирования не используются.

### 3. Опубликовать сайт и открыть админ-панель

1. Замени адрес в `docs/config.js` на адрес Worker из первого шага. Меняется только значение `apiBase`. Не добавляй в этот файл секреты или Telegram ID.
2. На GitHub открой **Settings → Pages** и включи публикацию из ветки `main`, папка `/docs`.
3. Убедись, что страница открывается по адресу `https://dharma2500.github.io/Vitaly-Video-Suggestions/`.
4. В BotFather настрой запуск Web App для своего бота и укажи HTTPS-адрес админ-панели: `https://dharma2500.github.io/Vitaly-Video-Suggestions/admin.html`. Названия меню BotFather могут отличаться, в зависимости от типа Mini App.
5. Отправь боту `/start`, а затем `/admin`. Кнопка откроет админ-панель внутри Telegram. Если открыть `admin.html` обычной вкладкой браузера, сервер не выдаст доступ к модерации.

Перед публичным запуском проверь приложение: `npm test`. После изменения серверного кода выполняй `npx wrangler deploy`.

## Возможности админ-панели

- Просмотр всех заявок и поиск по названию, нику или числовому ID.
- Одобрение, отклонение, отметка «просмотрено» и удаление заявки.
- Бан пользователя прямо из его заявки или вручную по Telegram ID.
- Просмотр списка банов и разбан.
- Ни один ник пользователя не используется как ключ для действий.

## Ограничения и приватность

Публичная страница показывает только одобренные и просмотренные заявки. Баны очищают предложения из базы приложения, но не могут удалить то, что уже было скопировано или переслано Telegram вне этой системы. Таблица банов намеренно хранит ID, пока бан действует. Секреты и ID администратора не должны попадать в клиентский JavaScript; ID администратора Worker читает только из Cloudflare Secret `ADMIN_TELEGRAM_ID`.
